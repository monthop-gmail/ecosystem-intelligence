# Event handoff

ที่ทางสำหรับ `event/v1` ที่ `ecosystem-intelligence` ปล่อยออกมา
— ตอบ [devfactory-core#32](https://github.com/monthop-gmail/devfactory-core/issues/32)

| ไฟล์ | คืออะไร | ใช้ยังไง |
| --- | --- | --- |
| `sample.jsonl` | ตัวอย่างที่**ตรึงเวลาไว้** ผลเหมือนเดิมทุกครั้ง | ให้ปลายทางเขียนเทสต์ยิงกับของจริงได้โดยไม่ต้องรอ service |
| CI artifact `ecosystem-events` | ข้อมูล**สด**จากทุกรอบที่ CI รัน | ดึงไปดูสภาพจริงตอนนั้น |

## ทำไมเป็นไฟล์ ไม่ใช่ HTTP

ตอนเปิด issue เราเสนอสามทาง (webhook / ดึงจาก API / broker) โดยไม่ได้ตรวจว่าทางไหน
**มีอยู่จริง** — `devfactory-core` ตรวจให้แล้วพบว่าไม่มีสักทาง เราไม่มี endpoint สำหรับ
event เขาไม่มี endpoint รับ และ broker ก็ยังไม่มีใน ecosystem

artifact handoff เป็นทางที่ **ไม่ต้องสร้างอะไรเลยทั้งสองฝั่ง** และพิสูจน์ว่าท่อไหลได้จริง
ก่อนตัดสินใจลงทุน — ไม่ใช่คำตอบระยะยาว

## รูปแบบ

JSON Lines — หนึ่งบรรทัดหนึ่ง event อ่านทีละใบได้โดยไม่ต้องโหลดทั้งก้อน
key เรียงแล้ว (`sort_keys`) เพื่อให้ diff อ่านรู้เรื่อง

ทุกใบ conform กับ `event/v1` ที่ pin ไว้ใน [`conformance/pinned.yaml`](../../conformance/pinned.yaml)
— CI ตรวจทั้งความถูกต้องตาม schema และว่าไฟล์นี้ยังตรงกับสิ่งที่ emitter ผลิตจริง

```bash
make emit-sample     # สร้างใหม่ (ตรึงเวลา 2026-01-01T00:00:00Z)
make emit            # ข้อมูลสด ออก stdout
```

## `event_id` ผูกกับเนื้อหา ไม่ใช่เวลา — อ่านซ้ำได้โดยไม่เกิดใบซ้ำ

id ของทุกใบมาจาก hash ของ **เนื้อหา** (ทีม · คำถาม · สถานะ ecosystem ณ ตอนนั้น · ตัวข้อเสนอ)
ไม่ได้มาจากเวลาที่รัน

    คำแนะนำชุดเดิมบน ecosystem สถานะเดิม  →  id เดิมเสมอ
    ecosystem ขยับ หรือคำแนะนำเปลี่ยน     →  id ใหม่

**นี่คือเงื่อนไขที่ทำให้ปลายทางไม่ต้องมี cursor** — อ่านไฟล์ทั้งกองซ้ำกี่รอบก็ได้
ใบที่เคยรับไปแล้วจะถูกปฏิเสธด้วย `event_id` ซ้ำที่ขอบของผู้รับเอง

## `sequence` เรียงภายใน subject — และ subject คือ "รอบ" ไม่ใช่ "ข้อเสนอ"

`ADVISORY_ISSUED` ทุกใบในรอบเดียวกันใช้ `subject_id` เดียวกัน แล้ว `sequence` เดินตามลำดับ
ความสำคัญของข้อเสนอ · `ECOSYSTEM_DRIFT_DETECTED` **ไม่มี `sequence`** เพราะแต่ละ finding
เป็นเรื่องของ entity คนละตัว ไม่มีลำดับระหว่างกัน

> รอบแรกเราให้แต่ละข้อเสนอเป็น subject ของตัวเอง ทำให้ทุก subject มี event ใบเดียว
> `sequence` เป็น `1` ตลอดและไม่พาข้อมูลลำดับไปเลย — `devfactory-core` จับได้ตอนทดสอบ
> intake ([#32](https://github.com/monthop-gmail/devfactory-core/issues/32))

## เวลาในตัวอย่างเป็นของปลอมโดยตั้งใจ

`occurred_at` ถูกตรึงไว้ที่ `2026-01-01T00:00:00Z` — **ห้ามเอาไปใช้เป็นเวลาจริง**
ข้อมูลสดอยู่ใน CI artifact

## เนื้อหาเปลี่ยนได้ รูปร่างไม่เปลี่ยน — เขียนเทสต์ยังไงให้ไม่พัง

`occurred_at` ตรึงไว้ก็จริง แต่ **เนื้อหาของคำแนะนำขึ้นกับสภาพ ecosystem ตอนที่สร้าง**
— มันอ้างถึง issue ที่เปิดค้างอยู่ และบอกว่า "ขยับล่าสุดกี่วันก่อน" ซึ่งเปลี่ยนทุกวัน

CI ของเราจึงตรวจ **รูปร่าง** ไม่ใช่ไบต์ ([`tools/check_sample_shape.py`](../../tools/check_sample_shape.py))
— key ที่มี · `event_type` · `subject_type` · `record_type` · `source.kind`

**สิ่งที่ยึดได้:** schema ของ `event/v1` · ชุด key · ค่าของ `event_type` และ `record_type`
**สิ่งที่ยึดไม่ได้:** ข้อความใน `metadata.title` / `why` · `references` ที่ชี้ไป issue
· จำนวน event ต่อรอบ

ถ้าต้องการไบต์ที่นิ่งจริง ๆ ให้ pin commit ของไฟล์นี้ในฝั่งท่าน แล้วเราจะแจ้งเมื่อรูปร่างเปลี่ยน
